# Analyst and visitor journeys

1. An analyst selects an authorized client. Show the snapshot date, coverage and queue freshness together. If no run exists, show pending scoring.
2. Filter the queue by review status, open an item, inspect units, timestamps and reason codes. Preserve client, filters and run when navigating back. A newer qualifying cutoff can present an Open case after a terminal review. Prior cases remain available in history.
3. Start the Open case or resume a Deferred case to enter In Review. Record an optional note with the decision. Confirm a completed intervention to enter Action Taken, pause the case as Deferred, or close it as No Action. Mark Action Taken as Resolved when review is complete. A conflicting edit refreshes the item and preserves the unsent note. A retry uses the same request key.
4. Revisit the case history to compare the reviewed baseline and a compatible later observation. The baseline window ends on or before the recorded action and the follow-up window starts on or after it. Show both observation cutoffs, windows and provenance. With only one snapshot or a later window that starts before the action, show “Follow-up unavailable” and explain which observation is needed. Observed changes do not establish intervention effects.
5. A portfolio visitor repeats the journey using a labeled synthetic fixture. The static adapter holds edits until reload.
