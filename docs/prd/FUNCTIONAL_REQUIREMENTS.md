# Functional requirements

|ID|Capability|Priority|Actor|Inputs|Behavior|Outputs|Dependency|Acceptance|Test|
|---|---|---|---|---|---|---|---|---|---|
|FR-01|Select client|Must|Analyst|session|List allowed clients|client IDs and labels|membership|Other tenants absent|authorization integration|
|FR-02|Inspect overview|Must|Analyst|client, cutoff|Aggregate dated inventory and counts|totals, window, coverage|observations|Empty client shows zero count and unavailable rates|SQL fixture|
|FR-03|Page queue|Must|Analyst|client, run, status, cursor|Pin ranking rows to run, sort by position and expose effective case status for the current queue|items and opaque cursor|published pointer and case lookup|Page traversal has unique items across publication. A qualifying item at a newer cutoff appears as Open after a terminal case|publication and case integration|
|FR-04|Inspect evidence|Must|Analyst|run and item|Join same-window measurements to reason codes|metric, unit, value, window|snapshot lineage|Every reason traces to an observation|contract fixture|
|FR-05|Record decision|Must|Analyst|case, evidence run, act/defer/no_action, expected version, note, request key|Append the decision once and atomically apply Action Taken, Deferred or No Action|event ID, case status and version|active In Review case and transaction|Matching retry returns original result. Act records the reviewed baseline and action event time|decision mapping and duplicate submission|
|FR-06|Update status|Must|Analyst|case or current candidate, evidence run, expected version, target, request key|Start Open or resume Deferred as In Review. Close Action Taken as Resolved|case, version and audit event|case lifecycle and optimistic locking|Stale update returns 409. Same-cutoff reruns create zero duplicate cases. A newer eligible cutoff can start a fresh case after a terminal state|concurrent writers, state machine and rescoring tests|
|FR-07|Read history|Must|Analyst|client, item and optional case|Return ordered immutable events across cases or for a specified case|case ID, actor, time, decision, transition and evidence reference|case and event records|Events survive reruns and a new case preserves prior cycles|integration replay|
|FR-08|Compare follow-up|Must|Analyst|item and case with an Action Taken event|Compare a reviewed baseline with a compatible later snapshot. The baseline window ends on or before the action and the later window starts on or after it|paired observed measures, windows, cutoffs and provenance, or unavailable reason|aligned observations and action event|One snapshot or a later window that starts before the action displays follow-up unavailable. A comparable later window shows a dated delta with source provenance|API contract and UI cases for single, incompatible and comparable snapshots|
|FR-09|Publish batch|Must|Operator|authorized snapshot manifest and immutable verified model artifact|Validate, run actual batch scoring and atomically publish|run metadata and model-generated queue|local scoring CLI and PostgreSQL|Failed run preserves prior queue. Before Phase 6 a local run publishes without registry or orchestration|CLI integration and fault injection|
|FR-10|Inspect provenance|Must|Analyst|run ID|Resolve immutable model ID, artifact SHA-256, feature schema version and observation cutoff|model metadata, run metadata and freshness|run manifest and model record|Metadata agrees with displayed queue and the verified artifact|API contract|
|FR-11|Explore demo|Must|Visitor|synthetic fixture|Simulate selection and review in browser memory|labeled demo views|static adapter|Reload resets edits and no API calls occur|browser network test|
