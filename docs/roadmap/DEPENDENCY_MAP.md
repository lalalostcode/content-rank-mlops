# Dependency map

Audit → architecture review → snapshot contract → feature matrix → grouped evaluation and verified local bundle → CLI publication and backend → integrated dashboard on authorized scoring output → registry and orchestration → recovery and CI → public handoff.

Backend reads can be designed against a synthetic run while ML work proceeds. The Product MVP gate requires approved local data and a freshly evaluated trained model. The local CLI publishes verified ranks using the same schema and publisher that Prefect will call in Phase 6. MLflow registry references are optional before Phase 6. Public demo fixtures share the API shape. Warehouse access and AWS are independent of all nine mandatory phases.
